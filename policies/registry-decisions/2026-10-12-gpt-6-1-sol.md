# 2026-10-12 — GPT-6.1 Sol replaces GPT-6 Sol (registry 0.9)

Human decision (operator, 2026-10-12): swap every `codex / gpt-6-sol`
candidate for `codex / gpt-6.1-sol`. Stage, tier and reasoning stay as they
were. The live launch probe passed the same day after the Codex usage limit reset.

## Changes

| Slot | Before (0.8) | After (0.9) |
|---|---|---|
| STRONG_IMPLEMENTER | `codex / gpt-6-sol / low` (STRONG, Stage 2) | `codex / gpt-6.1-sol / low` |
| DEEP_REASONER | `codex / gpt-6-sol / low` (STRONG, Stage 2) | `codex / gpt-6.1-sol / low` |
| INDEPENDENT_REVIEWER | `codex / gpt-6-sol / low` (STRONG, Stage 2) | `codex / gpt-6.1-sol / low` |
| ESCALATION_MODEL | `codex / gpt-6-sol / medium` (DEEP, Stage 3) | `codex / gpt-6.1-sol / medium` |

- `model_family` stays `gpt-6`, so reviewer disjointness does not change.
- Reasoning stays `low` in Stage 2. GPT-6.1 Sol's largest gain is at low
  effort, and Codex quota is already tight. Raise STRONG_IMPLEMENTER to
  `medium` later only if Stage 2 attempts fail noticeably more often.
- Codex `ultra` effort is never dispatched: it makes Codex delegate to its
  own subagents, outside Orca supervision.
- `gpt-6-astra` (also in the Codex cache) is not adopted.
- `tests/routing-cases.yaml`: every `gpt-6-sol` reference (pins,
  `disable_models`, `excludeFailedModels`, dispatch commands) now uses
  `gpt-6.1-sol`. Expected outcomes are otherwise unchanged.
- Docs also record the agy catalog change seen the same day: agy 1.3.3 now
  lists `claude-sonnet-5-5-{low,medium,high}` and
  `claude-opus-5-5-{low,medium,high}` instead of the Claude 4.6 single ids.
  No registry candidate uses agy's Claude entries, so this is documentation
  only.
